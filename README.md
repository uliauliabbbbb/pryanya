## 📌 О проекте

«Пряня» — это полностью рабочий интернет-магазин авторских пряников, написанный с нуля как
**курсовая работа по базам данных**. Проект охватывает весь цикл разработки: проектирование
реляционной схемы, REST API, фронтенд-приложение и панель администратора.

Я сделала упор не на «лишь бы работало», а на инженерную аккуратность: продуманную схему БД
с правилами целостности, типобезопасный код от запроса к базе до React-компонента и понятную
архитектуру, которую легко читать и расширять.

> ⚠️ **О контенте.** Это учебный, некоммерческий проект. Все изображения товаров и логотип
> **сгенерированы нейросетью** — реальные фотографии и бренды не использовались. Тексты,
> названия и цены вымышлены.

## ✨ Возможности

**Витрина (для покупателя):**

## 🧰 Технологии и почему именно они

### Frontend
| Технология | Зачем выбрана |
|---|---|
| **React 19 + TypeScript** | Компонентный UI и строгая типизация — меньше ошибок ещё на этапе написания кода |
| **Vite** | Молниеносная сборка и hot-reload, современный стандарт вместо устаревшего CRA |
| **Tailwind CSS** | Быстрая вёрстка по дизайн-системе из Figma без «зоопарка» CSS-файлов |
| **Zustand** | Лёгкое управление состоянием (корзина, авторизация) без бойлерплейта Redux |
| **React Router** | Клиентская маршрутизация для SPA |
| **Axios** | Удобные HTTP-запросы к API с перехватчиками и cookie-авторизацией |

### Backend
| Технология | Зачем выбрана |
|---|---|
| **Express** | Минималистичный и проверенный фреймворк для REST API |
| **Prisma ORM** | Типобезопасный доступ к БД и автогенерация миграций — схема описана в одном файле |
| **PostgreSQL** | Надёжная реляционная СУБД; ключевое требование курсовой по базам данных |
| **JWT в httpOnly-cookie** | Безопасная авторизация без хранения токена в localStorage (защита от XSS) |
| **bcrypt** | Хеширование паролей — пароли никогда не хранятся в открытом виде |
| **Zod** | Валидация входящих данных на сервере, согласованная с типами TypeScript |
| **Multer** | Загрузка изображений товаров через админку |

## 🗄️ База данных (ядро курсовой)

Схема описана в Prisma и состоит из **16 таблиц** и **3 перечислений (enum)**. Основные сущности:

```
users ──< orders ──< order_items >── products >── categories
  │         │                          │
  │         └──> addresses             ├──< reviews
  │         └──> promo_codes           ├──< product_ingredients >── ingredients
  └──< cart_items                      └──< set_items >── sets
```

**Проектные решения, на которые стоит обратить внимание:**

- **Снапшоты в заказах** — `order_items` хранит копию названия, цены и фото товара на момент покупки
  (`name_snap`, `price_snap`, `photo_snap`). Заказ остаётся корректным, даже если товар позже
  изменили или удалили — это исторические данные, а не «живая» ссылка.
- **Продуманные правила удаления** — `onDelete`: `Restrict` для каталога (нельзя удалить товар из
  активного заказа), `Cascade` для пользовательских данных, `SetNull` для исторических связей.
- **Связи «многие-ко-многим»** через явные таблицы-связки с дополнительными атрибутами:
  `product_ingredients` (порядок состава), `set_items` (количество в наборе).
- **`Decimal` для денег** вместо `float` — без ошибок округления в ценах и суммах.
- **Денормализация для скорости** — `rating_avg` и `reviews_count` хранятся в товаре, чтобы не
  пересчитывать агрегаты при каждом запросе каталога.
- **Индексы** на внешних ключах и полях сортировки (например, `created_at DESC` для заказов).
- **Enum'ы на русском** через Prisma `@map` — читаемые значения статусов прямо в БД.

📄 Подробное описание схемы и обоснование решений — в [`docs/db-design.md`](docs/db-design.md),
материалы к защите — в [`docs/db-defense.md`](docs/db-defense.md).

## ⚙️ Запуск локально

**Требования:** Node.js 20+, PostgreSQL 15+, созданная пустая БД `pranya`.

```bash
# 1. Backend
cd server
npm install
cp .env.example .env          # пропиши DATABASE_URL и секреты
npm run prisma:migrate        # применить миграции
npm run db:seed               # заполнить тестовыми данными
npm run dev                   # API на http://localhost:4000

# 2. Frontend (в новом терминале)
cd client
npm install
npm run dev                   # приложение на http://localhost:5173
```

### Переменные окружения (`server/.env`)

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | строка подключения к PostgreSQL |
| `PORT` | порт API (по умолчанию `4000`) |
| `JWT_SECRET` | секрет для подписи JWT-токенов |
| `JWT_EXPIRES_IN` | срок жизни токена (`7d`) |
| `COOKIE_SECRET` | секрет для подписи cookie |
| `CLIENT_ORIGIN` | origin фронтенда для CORS |

## 🔌 API

Базовый префикс — `/api`. В dev-режиме Vite проксирует `/api/*` на бэкенд.

| Группа | Назначение |
|---|---|
| `auth` | регистрация, вход, профиль (JWT в httpOnly-cookie) |
| `products` | каталог, карточка товара, похожие |
| `categories` | список категорий |
| `sets` | подарочные наборы |
| `orders` | оформление и история заказов |
| `promo` | проверка промокодов |
| `content` | FAQ, команда |
| `upload` | загрузка изображений (админка) |
